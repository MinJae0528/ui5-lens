# 테스트와 E2E: 왜, 어디서, 얼마에 쓰는가

기준일: 2026-11-19. 개수와 시간은 그날 실행한 값이며 코드가 바뀌면 달라집니다.

## 한 줄 요약

사용자가 화면에서 하는 흐름(검색 → 후보 선택 → 상세 보기)이 실제 브라우저에서 끝까지 되는지 **자동으로 눌러 보는 시험**이 E2E이고, 이 프로젝트는 **무료 도구만** 써서 **내 PC에서** 돌립니다. 지금까지 쓴 돈은 0원입니다.

## E2E가 무엇인가

E2E(End-to-End)는 "처음부터 끝까지"라는 뜻입니다. 프로그램이 브라우저를 직접 열고, 사람처럼 입력창에 글자를 치고 버튼을 누른 뒤 화면에 기대한 결과가 나왔는지 확인합니다.

| 시험 종류 | 무엇을 확인하나 | 이 프로젝트에서 | 한계 |
|---|---|---|---|
| 타입 검사 | 코드의 자료형이 맞는지 | `npm run typecheck` | 화면 동작은 모름 |
| 단위 테스트 | 함수 하나가 맞는 값을 내는지 | `npm test` (111개, 1초 이내) | 함수들이 화면에서 이어졌을 때 되는지는 모름 |
| **E2E** | **사용자 흐름이 브라우저에서 되는지** | `npm run test:e2e` (161개, 약 40초) | 느리고, 화면이 바뀌면 같이 고쳐야 함 |

## 왜 E2E를 쓰는가

이 앱은 함수가 맞아도 화면에서 깨질 수 있는 곳이 많습니다.

- **검색 → 후보 → 상세가 이어지는 흐름.** 주소(URL 해시)에 상태를 저장하므로, 새로고침이나 뒤로 가기에서도 같은 화면이 나와야 합니다.
- **같은 이름의 다른 클래스.** `sap.m.Table`과 `sap.ui.table.Table`의 메서드가 섞이지 않는지는 화면에서 탭을 눌러 봐야 압니다.
- **보안 설정.** 예제 실행 창(격리된 iframe)과 CSP가 실제 빌드에서 위반 없이 동작하는지는 브라우저에서만 확인됩니다.
- **키보드와 모바일.** 탭 이동(화살표 키), 모바일 폭에서 가로 스크롤이 없는지도 확인합니다.

사람이 매번 눈으로 145곳을 확인하면 시간이 오래 걸리고 빠뜨립니다. 코드를 고친 뒤 40초면 같은 확인을 되풀이할 수 있다는 것이 이유입니다.

## 어디서, 어느 수준으로 쓰는가

| 항목 | 현재 상태 |
|---|---|
| 도구 | Playwright(`playwright-core`, 무료 오픈소스) + 이미 설치된 Microsoft Edge |
| 실행 위치 | **내 PC만.** `npm run dev`로 서버를 띄운 뒤 `npm run test:e2e` |
| 규모 | 161개 확인 항목, 약 40초 |
| 자동 실행(CI) | **아직 안 함.** GitHub Actions는 타입 검사, 단위 테스트, 빌드, `npm audit`만 실행 |
| 인터넷 | 예제 실행 항목은 UI5 CDN 접속이 필요 |
| 확인 범위 | 4개 UI5 모드, 멤버 상세, 실패 주입, ABAP 문법 사전·tcode 사전, 모바일 폭, CSP 위반 0건 |

## 비용

| 항목 | 비용 |
|---|---|
| Playwright | 무료(오픈소스) |
| Edge 브라우저 | 무료(Windows에 포함) |
| 실행 위치 | 내 PC. 클라우드 서버 비용 없음 |
| GitHub Actions (공개 저장소) | 기본 서버는 무료. 다만 E2E를 CI에 붙이려면 자료 준비 문제가 있어 보류(아래) |
| Vercel 배포 | 무료 플랜 사용 중(E2E와 별개) |

**유지 비용은 돈이 아니라 시간입니다.** 화면 구조가 바뀌면 E2E의 기대값도 고쳐야 합니다. 실제로 ABAP 항목을 늘릴 때마다 "그룹 칩 9개"나 "tcode 11개" 같은 고정 숫자를 새 값으로 고쳤습니다. 그래서 화면 구조를 바꾸지 않는 데이터 추가는 단위 테스트가 먼저 잡고, E2E는 마지막에 한 번 돌립니다.

## 하지 않는 것과 다음 단계

- **CI에서 E2E 실행:** 보류했습니다. E2E는 UI5 31개 버전의 공식 자료로 만든 `public/data`(약 177MB)가 있어야 돌아가는데, 이 폴더는 저장소에 올리지 않고(`.gitignore`) 내 PC에서 `ui5.sap.com`을 내려받아(원본 캐시 약 113MB) 만듭니다. CI에서 하려면 매번 SAP 서버에서 다시 받아야 해서 느리고 네트워크에 의존하며, SAP 이용약관 확인(미완료)과도 얽힙니다. 대안은 작은 시험용 자료 묶음을 따로 만들어 E2E를 그 자료로 돌리는 것이며, 이는 별도 작업(기획 → 설계 → 코드)으로 진행합니다. 그 전까지는 push 전에 내 PC에서 직접 돌립니다.
- **유료 서비스(Cypress Cloud, BrowserStack 등):** 쓰지 않습니다. 여러 브라우저·기기 동시 시험이 필요해질 때까지 필요 없습니다.
- **미검증:** 실제 배포 서버의 응답 헤더, 스크린리더를 포함한 접근성 전체 점검.

## 실행 방법

```bash
npm run dev          # 서버 (자료 빌드 약 1~2분)
npm run test:e2e     # 다른 터미널에서. 끝나면 통과/실패 개수를 출력
```
