# UI5 Lens 프로젝트 설계서

문서 버전: 1.0  
구현 확인 기준일: 2026-11-05

UI5 Lens는 API 이름이나 기능 키워드를 입력하면 후보를 비교하고, 선택한 API의 구조·사용 조건·예제를 공식 출처와 함께 탐색하는 서비스이다. 이 문서는 현재 데이터 구조와 주요 처리 규약을 설명하며, 향후 개선안은 별도로 구분한다.

## 1 목표와 범위

- 동명 API를 정식 이름과 라이브러리로 구분한다.
- 속성, 메서드, 이벤트, Aggregation, Association을 종류별로 탐색한다.
- 직접 선언한 항목과 상속받은 항목을 구분한다.
- 버전별 존재 여부와 deprecated 상태를 확인한다.
- 한국어 해설, 공식 사실, 서비스 작성 예제를 구분한다.

로그인·결제·협업, 서버 기반 검색 이력, 실시간 AI 채팅, ABAP 문서 검색, Fiori 전체 본문 통합은 현재 범위에 포함하지 않는다.

## 2 기술 구성

| 구분 | 구성 | 선택한 역할 |
| --- | --- | --- |
| 화면 | React, TypeScript | 컴포넌트 기반 화면과 상태 관리 |
| 개발 및 빌드 | Vite, Node.js | 앱 번들 생성과 자료 준비 스크립트 |
| 데이터 | JSON, gzip 번들 | 버전별 정적 자료 및 한국어 설명 |
| 탐색 상태 | URL 해시, React 상태 | 주소 기반 탐색과 화면 전환 |
| 브라우저 저장 | localStorage | 마지막 UI5 버전 선택 |
| 추천 | 용어 사전, 가중치 기반 순위 | 외부 AI 호출 없이 관련 후보 제시 |
| 검증 | TypeScript, Node 테스트, Playwright와 Edge | 타입·도메인·브라우저 흐름 검사 |

정확한 의존성 선언과 설치 버전은 `package.json`과 `package-lock.json`을 기준으로 한다.

구조도와 책임 분리는 [시스템 아키텍처](system-architecture.md), [MVC 역할 설계](mvc-design.md)를 참고한다.

## 3 데이터 모델

| 개체 | 주요 필드 | 역할 |
| --- | --- | --- |
| VersionList | baseMinor, discoveredAt, versions | 기준 버전과 사용 가능한 버전 목록 |
| Meta | minor, version, fetchedAt, builtAt, docBase, counts, libraries | 수집·빌드 시점, 라이브러리별 자료 버전, 제공 범위 |
| IndexEntry | n, b, l, k, ko | 정식 이름, 짧은 이름, 라이브러리, 종류, 한국어 상태 |
| ApiDoc | name, library, kind, extends, sourceUrl, officialHash, 멤버 배열 | 버전별 공식 API 구조 |
| KoDoc | api, baseMinor, hashes, provenance, basedOn, overview, members, usage, examples | API별 한국어 설명과 검토 상태 |
| Availability | versions, symbols | 심볼별 버전 존재 여부와 deprecated 상태 |
| MemberLife | 심볼, 종류·이름 키, 상태 문자열 | 멤버별 버전 가용성 |
| RawMembers | 클래스 이름표, 압축 멤버 튜플 | 멤버 검색과 추천용 색인 |
| TopicNode | key, 제목, 자식 목록 | 공식 문서 목차 트리 |

### 식별 규칙

- API의 논리적 식별자는 버전과 정식 이름의 조합이다. `Table`만으로 식별하지 않는다.
- 한국어 멤버 키는 `method:setText`처럼 종류와 이름을 결합한다.
- 멤버 가용성 자료는 `m:setText` 등의 축약 접두사를 사용한다. 변환 규칙은 도메인 모듈에서 관리한다.
- 가용성은 버전 순서에 대응하는 문자열로 표현한다. `0`은 없음, `1`은 있음, `2`는 deprecated 상태이다.

### API와 한국어 설명의 관계

`ApiDoc`의 자료형·기본값·상속·도입·deprecated 정보는 공식 자료에서 얻는다. `KoDoc`는 한국어 설명과 사용 맥락을 담당한다. 한국어 설명이 공식 사실 값을 별도로 덮어쓰는 구조로 사용하지 않는다.

## 4 정적 자료 인터페이스

아래 경로는 앱의 데이터 기준 경로 아래에 위치하는 정적 파일이다. 서버 비즈니스 API 엔드포인트가 아니다.

| 상대 경로 | 용도 | 로딩 시점 |
| --- | --- | --- |
| `data/versions.json`, `data/availability.json`, `data/aliases.json` | 버전 목록·전역 가용성·별칭 | 앱 시작 |
| `data/v/{minor}/meta.json`, `data/v/{minor}/index.json.gz` | 선택 버전의 범위와 검색 색인 | 버전 선택 |
| `data/v/{minor}/lib/{library}.json.gz` | 라이브러리 단위 API 상세 | 상세 최초 조회 |
| `data/ko/{API}.json` | 한국어 설명과 예제 | 상세 조회 |
| `data/v/{minor}/members.json.gz` | 멤버 검색 색인 | 멤버 검색 필요 시 |
| `data/v/{minor}/intent.json.gz`, `data/intents.json` | 추천 말뭉치와 한국어 용어 사전 | 기능 추천 |
| `data/members/{shard}.json.gz` | 멤버 버전 가용성 | 버전 정보 조회 |
| `data/v/{minor}/topics.json.gz` | 문서 목차 | 가이드 진입 |

멤버 가용성 자료는 8개 샤드로 나뉜다. `{shard}`는 0부터 7까지이다. 가변 파일 이름은 로더의 인코딩 규칙을 따른다.

## 5 검색과 상세 처리

### 이름 검색

1. 입력이 멈춘 뒤 120ms 디바운스를 거쳐 검색어를 확정한다.
2. 선택 버전의 색인과 등록된 한국어 별칭을 사용한다.
3. 전체 이름 일치, 짧은 이름 일치, 일부·별칭 일치 순으로 정렬한다.
4. 동명 후보를 각각 표시하고 선택한 정식 이름으로 상세를 연다.

### 멤버 검색

`setText`, `Button#setText` 등으로 멤버를 찾는다. 종류와 이름이 같은 멤버는 선언 클래스 목록으로 묶는다. 자동 생성 접근자와 deprecated 항목은 표시·정렬 규칙을 적용한다.

### 기능 추천

한국어 표현을 용어 사전으로 영어 검색어와 연결하고, 선택 버전의 공식 이름·설명·멤버 이름에서 일치 정도를 계산한다. 추천 이유와 해석에 사용한 용어를 제공한다. 추천 결과는 정답이나 범용 자연어 이해를 보장하지 않는다.

### 상세 자료 조합

`loadDetail`은 자기 API, 부모 체인, 한국어 설명을 조합한다. 부모 자료 일부를 불러오지 못하면 불완전한 상속 상태를 알린다. 도메인 함수가 상속 멤버를 병합하고 선언 위치를 보존한다.

## 6 상태와 갱신

| 상태 | 저장 위치 | 내용 |
| --- | --- | --- |
| 탐색 주소 | URL 해시 | v, q, api, tab, inh, mq, m, kf, lib, mem, tp |
| 화면 상태 | React | 입력 중인 값, 선택 위치, 펼침 상태, 로딩과 오류 |
| 마지막 버전 | localStorage | `ui5lens.version` |
| 자료 캐시 | 메모리 | 버전·라이브러리·색인 등의 Promise 캐시 |

탐색 모드는 `name`, `feature`, `browse`, `guide`이다. 버전은 유효한 URL 값, 마지막 선택, 기준 버전 순으로 결정한다.

### 한국어 검토 상태

| 조건 | 상태 |
| --- | --- |
| 한국어 설명이 없음 | none |
| 기준 원문 해시 일치, 미검토 | draft |
| 기준 원문 해시 일치, 사람 검토 완료 | reviewed |
| 선택 버전의 원문 해시 불일치 또는 미확인 | stale |

`stale`은 검토 완료 표시보다 우선한다. `ko:stamp`는 원문 대조 기준을 기록하는 작업이며 사람 검토 완료와 같은 의미가 아니다. 부가 정보 일부는 해시 대상 밖에 있으므로 해시 일치가 모든 부가 설명의 동일성을 보장하지 않는다.

## 7 화면 설계

| 화면 | 제공 내용 | 요구사항 |
| --- | --- | --- |
| 공통 상단 | 버전 선택, 자료 범위, 공식 사이트 연결 | FR-17, FR-20 |
| 이름과 메서드 | 검색창, 종류 필터, 클래스 후보, 멤버 그룹 | FR-01~06 |
| 기능으로 추천 | 해석 용어, 추천 후보와 이유, 한계 표시 | FR-07 |
| API 탐색 | 라이브러리별 목록과 필터 | FR-08 |
| 문서 가이드 | 공식 목차, 영어 제목 검색, 본문 링크 | FR-22 |
| API 상세 | 개요, 생성자, 5종 멤버, 상속, 사용 흐름, 예제, 버전 | FR-09~18 |

모든 내용을 한 페이지에 펼치기보다 전체 구조를 먼저 보여 주고 필요한 항목을 선택하도록 구성한다. 작은 화면에서도 후보와 상세 사이를 이동할 수 있어야 한다.

## 8 오류 및 보안 설계

- 필수 자료 조회 실패를 가짜 데이터로 대체하지 않는다.
- 한국어 미제공, 실제 검색 결과 없음, 네트워크 실패는 구분해야 한다. 일부 선택 자료의 오류 구분은 보완 대상이다.
- 문서 HTML을 정화하고 앱의 콘텐츠 보안 정책을 적용한다.
- 예제는 전용 문서를 `sandbox="allow-scripts"` iframe으로 열어 실행한다.
- 예제의 실행 버전과 검증된 버전을 표시한다. 기준일의 실행기는 UI5 1.154.0을 사용한다.
- 보안 헤더 설정 파일과 실제 배포 응답의 적용 여부는 별도로 검증한다.

보안 관련 정책은 저장소의 `SECURITY.md`를 따른다. 이 문서에는 수정 전 문제의 재현 입력이나 환경별 진단 로그를 수록하지 않는다.

## 9 검증과 개선 계획

### 검증 단계

1. TypeScript로 앱과 테스트의 타입을 검사한다.
2. Node 테스트로 검색·추천·상속·버전 해석·상태 파싱을 확인한다.
3. 빌드된 앱에서 요구사항의 AC-01부터 AC-08까지 확인한다.
4. 예제를 해당 UI5 런타임에서 실행하고 렌더링 및 주요 조작을 검증한다.
5. 배포 환경에서 자료 파일, 보안 헤더, 오류 복구와 접근성을 확인한다.

### 향후 제안

| 우선순위 | 제안 | 완료 기준 |
| --- | --- | --- |
| 완료(2026-11-06) | 입력 검증 회귀 테스트 해결 | 단위 테스트 65개 통과 |
| P0 | 현재 한국어 상세의 사람 검토 | 검토한 내용에만 reviewed 표시 |
| 완료(2026-11-06) | 자료 없음과 통신 오류 구분(한국어·추천·문서 목차) | E2E로 실패 주입과 재시도 확인. 멤버 색인·문서 목차 조회 실패 화면은 미시험 |
| 완료(2026-11-06) | 4개 탐색 모드 회귀 검사 | AC-01~08 결과는 요구사항 정의서에 기록 |
| P1 | 성능·접근성·배포 검증 | 측정 환경과 결과 기록 |
| P2 | 한국어 대상 확장, 로딩 책임 정리 | 콘텐츠 검토 범위 및 모듈 책임 명시 |

새 서버, 데이터베이스, 실시간 AI 호출은 현재 설계에 포함된 기능이 아니다. 필요가 확인되면 별도 요구사항으로 검토한다.

## 10 관련 구현

- 데이터 규약과 접근: `src/types.ts`, `src/data.ts`
- 도메인 로직: `src/domain/`
- 상태와 제어: `src/controller/`
- 화면: `src/shell/`, `src/detail/`
- 자료 준비: `scripts/`, `data/ko/`
- 테스트: `test/`, `scripts/e2e.mjs`, `scripts/verify-examples.mjs`

검증 결과와 지원 범위는 [구현 현황](implementation-status.md)을 참고한다.
