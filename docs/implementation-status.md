# UI5 Lens 구현 현황

구현 확인 기준일: 2026-11-06

핵심 검색과 상세 탐색, 버전 선택 및 확장 탐색 기능이 구현되어 있다. 한국어 설명의 사람 검토와 접근성 전체 인수, 실제 배포 검증은 남아 있다. 아래 수치는 기준일의 점검 결과이며 최신 CI나 배포 상태를 대신하지 않는다.

## 확인한 기능

- 이름·메서드 검색: 전체 이름, 짧은 이름, 대소문자 변형, 등록된 한국어 별칭, `Button#setText` 형태의 클래스 지정 멤버 검색
- 동명 API 후보 분리와 선택한 API의 상세 조회, 멤버 전용 상세(설명·사용법·버전·쓸 수 있는 클래스)
- 속성·구성 요소·참조 관계·이벤트·메서드와 상속 탐색, 생성자 탭
- 버전 선택, 존재 여부와 deprecated 상태 표시
- 한국어 설명의 AI 작성·검토·재검토 상태 표시
- 기능 추천: 공식 말뭉치와 한국어 용어 사전으로 컨트롤과 메서드·이벤트 후보를 이유와 함께 제시(검색 시 외부 AI 호출 없음)
- API 탐색(라이브러리 → 클래스)과 문서 가이드(목차 탐색·제목 검색·공식 문서 링크)
- 예제 코드 표시와 격리된 실행 구조

## 이번 갱신에서 바뀐 점

- **입력 검증**: URL 해시의 `api` 값을 정리했다. 실제 식별자(`sap.m.Button`, `module:sap/…`, 제네릭 표기)는 유지하고 경로 이탈(`..`), 이중 슬래시, 선행 `/`, 태그를 거부한다. 처음 고친 규칙이 `module:` 없는 선행 `/`를 허용해 재검증에서 다시 실패했고, 그 허점을 막았다. 31개 버전의 색인 이름 117,171개 중 규칙에 맞지 않는 것은 1개이며, 공식 자료에서 이름 자리에 설명 문장이 들어간 항목(“An enumeration for the application work protect mode state.”)이다. 이 항목은 검색 후보로는 보이지만 주소(URL)로 직접 여는 것은 거부된다. 자료 정규화에서 걸러낼지는 후속 결정이다.
- **한국어 “없음”과 “조회 실패” 구분**: 한국어 파일 유무는 색인 상태로 판단한다. 파일이 있어야 하는데 읽지 못하면 경고와 재시도를 보여 주고, 원래 없는 API는 “준비되지 않음”으로 표시한다.
- **추천 “결과 없음”과 “자료 로딩 실패” 구분**: 말뭉치·용어 사전·멤버 색인 중 하나라도 실패하면 결과 없음 문구 대신 실패 안내와 재시도를 보여 준다.
- **문서 목차 “없음”과 “실패” 구분**: 목차가 없는 버전은 요청하지 않고 없음으로 안내한다. 없는 파일에도 HTML을 돌려주는 서버에서 오류로 오인되던 문제를 막았다.
- 이름 검색 모드에서 문장을 입력하면 추천을 몰래 섞지 않고 기능 추천 모드로 안내한다.

## 추천 및 예제의 한계

추천 평가의 fresh 40문항에서 상위 3개 적중은 22개(55%)였다. 이는 저장된 평가 결과이며 이번 점검에서 재측정한 값은 아니다. 이 수치는 컨트롤(클래스) 추천 기준이다. 다른 튜닝용 평가 수치를 일반적인 정확도로 사용하지 않는다. 사전 변경 후에는 미사용 질문으로 다시 평가한다.

**추천 메서드·이벤트는 정확도가 낮다.** 사전과 점수 규칙을 맞추기 전에 만든 질문 30개(`data/recommend-members-eval.json`)를 한 번 측정한 결과, 상위 3개 안에 정답이 있었던 것은 3개(10%), 상위 8개는 5개(17%)였다(UI5 1.154). 화면은 이 수치를 고지하고 “실험적 기능”으로 표시한다. 실패의 큰 원인은 두 가지로 보인다: 정답이 되는 자동 생성 접근자(`setVisible`, `getSelectedItem` 등)를 추천 말뭉치에서 제외했고, 한국어 동사(열기·닫기·추가·가져오기)를 API 동사로 잇는 사전이 없다. 이 세트를 보고 사전을 고치지 않았으므로, 개선하려면 새 질문으로 다시 평가해야 한다.

기존 예제 4개는 UI5 1.154.0에서 기본 렌더링이 확인되었다. 예제 실행기는 1.154.0을 사용하므로 다른 UI5 버전을 선택해도 그 버전에서 검증된 것이 아니다. 모든 사용자 조작을 검증한 것도 아니다.

## 다음 작업

1. 현재 두 Table의 한국어 내용·출처·사용 조건을 사람이 검토한다(검토 전에는 `reviewed`로 바꾸지 않는다).
2. 추천 메서드·이벤트의 정확도를 높인다(접근자 포함 여부, 한국어 동사 사전). 개선 뒤에는 새 질문으로 다시 평가하고 공개 수치를 갱신한다.
3. 자료를 포함한 배포 결과와 응답 헤더를 검증한다.
4. 접근성(스크린리더, 전체 키보드 조작)을 확인한다.
5. 핵심 한국어 API 범위를 확장하고 검토 상태를 함께 갱신한다.
