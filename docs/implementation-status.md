# ERP Lens 구현 현황

구현 확인 기준일: 2026-11-06

핵심 검색과 상세 탐색, 버전 선택 및 확장 탐색 기능이 구현되어 있다. 한국어 설명의 사람 검토와 접근성 전체 인수, 실제 배포 검증은 남아 있다. 아래 수치는 기준일의 점검 결과이며 최신 CI나 배포 상태를 대신하지 않는다.

## 확인한 기능

- 이름·메서드 검색: 전체 이름, 짧은 이름, 대소문자 변형, 등록된 한국어 별칭, `Button#setText` 형태의 클래스 지정 멤버 검색
- 동명 API 후보 분리와 선택한 API의 상세 조회, 멤버 전용 상세(설명·사용법·버전·쓸 수 있는 클래스)
- 속성·구성 요소·참조 관계·이벤트·메서드와 상속 탐색, 생성자 탭
- 버전 선택, 존재 여부와 deprecated 상태 표시
- 한국어 설명의 AI 작성·검토·재검토 상태 표시
- 기능 추천: 공식 말뭉치와 한국어 용어 사전으로 컨트롤과 메서드·이벤트 후보를 이유와 함께 제시(검색 시 외부 AI 호출 없음)
- API 탐색(라이브러리 → 클래스)과 문서 가이드(목차 탐색·제목 검색·공식 문서 링크)
- 예제 코드 표시와 격리된 실행 구조

## 이번 갱신에서 바뀐 점

- **입력 검증**: URL 해시의 `api` 값을 정리했다. 실제 식별자(`sap.m.Button`, `module:sap/…`, 제네릭 표기)는 유지하고 경로 이탈(`..`), 이중 슬래시, 선행 `/`, 태그를 거부한다. 처음 고친 규칙이 `module:` 없는 선행 `/`를 허용해 재검증에서 다시 실패했고, 그 허점을 막았다. 31개 버전의 색인 이름 117,171개 중 규칙에 맞지 않는 것은 1개이며, 공식 자료에서 이름 자리에 설명 문장이 들어간 항목(“An enumeration for the application work protect mode state.”)이다. 이 항목은 검색 후보로는 보이지만 주소(URL)로 직접 여는 것은 거부된다. 자료 정규화에서 걸러낼지는 후속 결정이다.
- **한국어 “없음”과 “조회 실패” 구분**: 한국어 파일 유무는 색인 상태로 판단한다. 파일이 있어야 하는데 읽지 못하면 경고와 재시도를 보여 주고, 원래 없는 API는 “준비되지 않음”으로 표시한다.
- **추천 “결과 없음”과 “자료 로딩 실패” 구분**: 말뭉치·용어 사전·멤버 색인 중 하나라도 실패하면 결과 없음 문구 대신 실패 안내와 재시도를 보여 준다.
- **문서 목차 “없음”과 “실패” 구분**: 목차가 없는 버전은 요청하지 않고 없음으로 안내한다. 없는 파일에도 HTML을 돌려주는 서버에서 오류로 오인되던 문제를 막았다.
- 이름 검색 모드에서 문장을 입력하면 추천을 몰래 섞지 않고 기능 추천 모드로 안내한다.

## 추천 및 예제의 한계

추천 평가의 fresh 40문항에서 상위 3개 적중은 22개(55%)였다. 이는 저장된 평가 결과이며 이번 점검에서 재측정한 값은 아니다. 이 수치는 컨트롤(클래스) 추천 기준이다. 다른 튜닝용 평가 수치를 일반적인 정확도로 사용하지 않는다. 사전 변경 후에는 미사용 질문으로 다시 평가한다.

**추천 메서드·이벤트는 정확도가 아직 낮다.** 평가 질문은 세 묶음이며(`data/recommend-members-eval.json`), 어떤 묶음을 공개 수치로 쓰는지가 중요하다.

| 묶음 | 질문 수 | 상위 3개 적중 | 상위 8개 적중 | 의미 |
| --- | --- | --- | --- | --- |
| 개선 전 기준선(fresh) | 30 | 1개 (3%) | 3개 (10%) | 개선 전에 측정 |
| dev | 30 | 11개 (37%) | 18개 (60%) | 실패 원인을 보고 개선에 참고함. 성능 지표로 쓰지 않음 |
| fresh | 30 | 9개 (30%) | 13개 (43%) | 1차 개선 중 두 번 측정해 일부 오염됨. 성능 지표로 쓰지 않음 |
| **fresh2 (공개 수치)** | **20** | **3개 (15%)** | **6개 (30%)** | 마지막 개선 전에 작성해 개선 후 한 번만 측정(UI5 1.154) |

화면은 fresh2 수치를 고지하고 “정확도가 낮은 실험적 기능”으로 표시한다. 이번 개선은 세 가지다: 자동 생성 접근자를 추천 말뭉치에 포함, 같은 이름은 한 줄로 묶어 대표 클래스를 표시, 이름 정밀도(질문과 겹치는 낱말 비율)와 공통 API 가산 반영. 한국어 동사 사전(열기·닫기·추가·제거·가져오기·설정·변경·연결·해제·보이기·활성·값·선택·발생)도 추가했고, 평가 질문에만 있는 단어는 넣지 않았다. 이 과정에서 평가 질문(“팝오버 열기”)에서 떠올린 사전 항목(`openby`)이 오히려 순위를 해쳐 제거했다. 개선 중 컨트롤(클래스) 추천은 같은 평가에서 변하지 않았다(fresh 40문항 중 상위 3개 22개).

기존 예제 4개는 UI5 1.154.0에서 기본 렌더링이 확인되었다. 예제 실행기는 1.154.0을 사용하므로 다른 UI5 버전을 선택해도 그 버전에서 검증된 것이 아니다. 모든 사용자 조작을 검증한 것도 아니다.

### 추천 정확도 목표와 레시피 실험 (화면에는 연결하지 않음)

목표는 “추천 3개 안에 정답이 항상 하나는 있다”이다. 외부 AI 없이 단어·문구 매칭만으로는 자유로운 질문에 이를 보장할 수 없다. 이를 확인하려고 자주 하는 작업과 정답 API를 정리한 **레시피 84개**(`data/recipes.json`)를 만들었다. 정답이 1.154 공식 자료에 실제로 선언돼 있는지는 빌드가 검증한다(이 검증이 잘못 쓴 참조 8개를 잡았다). 레시피는 AI가 작성했고 사람이 검토하지 않았다.

문구 매칭(문자 2-그램 유사도)을 붙여, 레시피를 만든 뒤 문구를 바꿔 쓴 질문 42개(`data/recommend-hybrid-eval.json`)를 **한 번** 측정했다.

| 질문 묶음 | 질문 수 | 상위 3개 안에 정답 | 비고 |
| --- | --- | --- | --- |
| 레시피가 다루는 작업의 다른 표현 | 30 | 14개 (47%) | 17개만 레시피에 연결됐고, 연결된 17개 중 5개는 엉뚱한 레시피였다 |
| 레시피에 없는 작업 | 12 | 5개 (42%) | 일반 추정(정확도 낮음)으로 되돌아간 결과 |

문구 매칭이 단어 모양이 바뀌면 따라가지 못하고, `컨트롤` 같은 흔한 단어 때문에 엉뚱한 레시피가 연결된다. 틀린 레시피를 “검증된 추천”으로 보여 주면 현재 상태보다 해로워서 **화면에는 연결하지 않았다.** 매칭 로직, 레시피, 평가 장치(`npm run`이 아닌 `node scripts/eval-hybrid.mjs`)만 저장소에 남겼다. 이 질문 세트를 보고 매칭을 고치면 세트가 오염되므로, 개선한다면 새 질문으로 다시 평가한다.

#### 작은 모델 실험 (직접 학습, 화면에는 연결하지 않음)

100MB 규모의 내려받기는 로딩과 무게 면에서 부적합해서, 이 일만 하는 작은 모델을 직접 학습했다. 글자 2·3-그램과 조사를 뗀 낱말의 tf-idf 특징으로 레시피 84개를 분류하며(`src/domain/recipeModel.ts`, 학습은 `node scripts/train-recipe-model.mjs`), 모델 파일은 **470KB(압축 123KB)** 이고 외부 라이브러리 없이 브라우저에서 바로 계산된다. 학습 데이터는 레시피 문구 + AI가 쓴 다른 표현 504개 + 유의어 치환 증강으로 약 1,340개다.

| 평가 세트 | 용도 | 표에 있는 작업 | 표에 없는 작업 |
| --- | --- | --- | --- |
| 문구 매칭(이전 방식), fresh3 | 비교 기준 | 14/30 (47%) | 5/12 (42%) |
| 작은 모델, fresh3 | 확신도 기준을 정하는 데 사용(이미 본 세트) | 26/30 (87%) | 4/12 (33%) |
| **작은 모델, fresh4 (공개 수치)** | 학습 데이터를 만들기 전에 작성, 기준 고정 후 **한 번만 측정** | **18/30 (60%)** | **1/12 (8%)** |

fresh3의 87%는 기준을 그 세트로 정해 과대평가된 값이고, 새 질문에서는 60%로 내려갔다. 가장 큰 문제는 표에 없는 작업이다. 모르는 질문 12개 중 8개를 엉뚱한 레시피로 채택해 일반 추정(약 40%)보다 나빠졌다. 그래서 화면에는 연결하지 않았다. 목표인 “3개 안에 항상 정답”에는 이르지 못했고, 이 방식으로 100%는 불가능하다.

연결 조건은 새로 쓴 평가 질문에서 표에 있는 작업이 약 85% 이상이고 표에 없는 작업의 오채택이 약 10% 이하일 때로 정했다. 필요한 개선은 (1) 레시피당 학습 표현을 지금의 약 9개에서 수십 개로 늘리기, (2) 표에 없는 질문을 “해당 없음”으로 학습시키는 음성 표현 추가, (3) 레시피(작업) 범위 확대, (4) 개선 뒤 새 질문 세트로 재평가다. 학습 표현과 평가 질문을 같은 작성자(AI)가 썼으므로 평가는 완전히 독립적이지 않다는 한계도 있다.

## 다음 작업

1. 현재 두 Table의 한국어 내용·출처·사용 조건을 사람이 검토한다(검토 전에는 `reviewed`로 바꾸지 않는다).
2. 추천 메서드·이벤트의 정확도를 더 높인다(예: 동사와 대상 명사를 함께 보는 규칙, 클래스 추천 결과와의 결합). 개선 뒤에는 새 질문으로 다시 평가하고 공개 수치를 갱신한다.
3. 자료를 포함한 배포 결과와 응답 헤더를 검증한다.
4. 접근성(스크린리더, 전체 키보드 조작)을 확인한다.
5. 핵심 한국어 API 범위를 확장하고 검토 상태를 함께 갱신한다.

## 2026-11-10 이후 변경 (위 표의 기준일 2026-11-05 이후)

- 이름을 UI5 Lens 에서 ERP Lens 로 바꿨다.
- 한국어 설명이 없는 모든 API·멤버에 공식 설명 첫 문장의 자동 번역(Claude Haiku 5.5, AI 초안·미검토)을 붙였다. 31개 버전, 고유 문장 44,877개, 비용 약 $1.7. 화면에 "자동 번역" 표시가 붙는다.
- 인기 API 65개에 한국어 간단판을 추가했다(예제·사용 순서 없음).
- "ABAP 기본" 탭을 추가했다. 기본 문법 33개의 AI 초안이며 ABAP 시스템에서 실행해 검증하지 않았다. 공식 링크는 SAP-samples/abap-cheat-sheets 에 실제로 쓰인 주소만 사용한다.
- 멤버 펼침에 공식 설명 링크를 추가했다. 위 구현 확인 수치 중 한국어 상세·문서 범위 외의 항목은 이 날짜 이후 다시 확인하지 않았다.
