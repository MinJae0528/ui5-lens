# UI5 Lens 요구사항 정의서

문서 버전: 1.0  
구현 확인 기준일: 2026-11-06

한국어 기반 UI5 API 탐색 서비스

UI5 Lens는 UI5 개발자가 API 이름이나 하고 싶은 일을 입력하면 후보를 비교하고, 선택한 API의 구조와 사용 조건을 공식 근거와 함께 탐색하는 웹앱이다. 이 문서는 개발과 기능 검증의 기준으로 사용할 기능 요구사항, 품질 요구사항 및 인수 기준을 정의한다.

> 이 문서는 서비스 목표와 구현 확인 기준일의 코드를 대조해 작성했다. 구현 여부는 전체 요구사항의 인수 완료를 의미하지 않는다. 특히 한국어 상세 설명은 현재 2개 API에만 제공되며, 사람 검토 완료 항목은 없다.

### 2 해결할 문제

- 영어 API 문서의 여러 구역을 오가며 속성·메서드·이벤트를 찾는 데 시간이 걸린다.
- Table처럼 짧은 이름이 같아도 라이브러리와 사용 목적이 달라 올바른 후보를 선택해야 한다.
- 상속된 항목, 버전별 존재 여부, deprecated 상태와 실제 사용 조건을 함께 이해해야 한다.

### 3 우선순위와 상태 표기

**P0**는 핵심 탐색과 정확성을 위한 필수 항목, **P1**은 현재 확장 기능 또는 제품 완성도를 높이는 항목이다. “구현 확인”은 코드 또는 제한된 동작 확인, “부분 구현”은 일부 데이터·조건만 충족, “미검증”은 이번 검증 범위 밖이라는 뜻이다.

| FR-07 / P1 | 기능 설명으로 추천 / 한국어 용어 사전과 공식 말뭉치로 클래스 및 멤버 후보를 추천하고 일치 이유를 표시한다. 검색 시 외부 AI 호출은 하지 않는다. | 구현 확인 / 정확도 제한 |

> 추천의 역할은 관련 API 후보를 제시하는 것이다. 자연어의 의미를 완전히 이해하거나 정답을 보장하는 기능으로 정의하지 않는다.

## 범위에 포함하지 않는 기능

로그인·결제·협업, 즐겨찾기·학습 이력, 서버형 질의 API, 실시간 LLM 채팅, ABAP 문서 검색, Fiori 전체 본문 통합은 현재 구현 범위 밖이다. Fiori 관련 공식 참고 링크는 일부 제공된다.

> 초기 “검증할 컴포넌트 약 10개” 목표는 아직 충족하지 못했다. 반면 31개 버전, 멤버 검색, 문서 목차 탐색은 초기 최소 범위를 넘어 구현된 확장이다.

| AC-01 동명 API | 확인: Table 검색에서 두 Table 후보 분리, 후보를 바꿔도 이름·멤버가 섞이지 않음 | 없음 |
| AC-02 이름과 별칭 | 확인: 대소문자 변형, “표”, “팝업”, “입력창”이 등록한 후보로 연결되고 중복 없음 | 없음 |
| AC-03 멤버 탐색 | 대부분 확인: 멤버 검색 → 선언 클래스 선택 → 멤버 상세 4탭 → 클래스로 복귀, `Button#setText` 클래스 지정 | 상세의 “관련 항목” 링크 클릭 이동은 자동 시험하지 않음 |
| AC-04 상속과 필터 | 확인: 직접 선언·상속 전환, 이름·한국어 설명 필터, deprecated 필터 | 없음 |
| AC-05 버전 변경 | 확인: 버전 전환, 없는 항목 안내, 도입·제거 시점의 불확실 구간 표기 | 1.154 → 1.120 외 모든 쌍을 시험한 것은 아님 |
| AC-06 예제 검증 | 부분 확인: 예제 4개를 1.154.0으로 재실행해 기본 렌더링 통과, 1개는 앱의 격리 iframe에서도 렌더링 | 4개 재실행은 통과(1.154.0). 주요 조작 확인과 다른 버전에서의 실행은 남음 |
| AC-07 실패와 복귀 | 대부분 확인: 없는 검색어, 한국어 없음, 한국어 조회 실패(재시도 복구), 추천 자료 실패(재시도 복구), 문서 목차 없음, 라이브러리 번들 지연·실패 | 멤버 색인 실패와 문서 목차 조회 실패 표시는 구현했으나 자동 시험하지 않음 |
| AC-08 입력과 접근성 | 부분 확인: 잘못된 해시(`api=../../etc/passwd` 등)가 채택되지 않음, 뒤로 가기·키보드 이동·작은 화면 복귀, 390px 가로 넘침 없음 | 스크린리더와 전체 키보드 조작은 별도 수행 |

## 인수 완료 조건

- 타입 검사와 단위 테스트를 모두 통과하고, 인수 시나리오별 결과·실행 환경·날짜를 남긴다.
- 한국어 지원 범위와 검토 완료 수를 실제 데이터와 일치시킨다. 10개 목표를 유지할지 2개 집중 검증으로 조정할지는 제품 범위 결정으로 남긴다.
- 최종 빌드에 필요한 JSON·gzip 파일을 모두 포함하고, 호스트의 CSP와 예제 실행 경계를 확인한다.

## 문서 간 연결

구현 구조와 데이터 규약은 [프로젝트 설계서](project-design.md)를, 검사 결과와 남은 작업은 [구현 현황](implementation-status.md)을 따른다. 요구사항 ID는 이후 이슈·테스트·발표 자료에도 동일하게 사용한다.


## 관련 구현

- 이름 검색: `src/domain/search.ts`
- 멤버 검색: `src/domain/memberIndex.ts`
- 화면 제어: `src/controller/useSearchController.ts`
- 상세 화면: `src/detail/`
- 자료 접근 및 타입: `src/data.ts`, `src/types.ts`
- 자료 생성: `scripts/build-data.mjs`

문서의 구현 상태는 기준일의 결과이며, 이후 변경 사항을 자동으로 반영하지 않는다.
